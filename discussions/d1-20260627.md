1. The Core Architecture Decision: The "Three-Layer Ward" (三层结界)
You correctly identified that it's not a choice of "just Terraform" or "just Caddy." We are going with a highly specific hybrid model, but with a crucial modernization: We are choosing WASM over gRPC for our primary plugin ecosystem.

Our target architecture consists of three distinct planes:

Layer 1: The Go Host / Body (The Caddy Pattern - In-Process Pipeline)

What it is: The extremely low-latency, zero-copy Go core. It handles HTTP proxying, SSE streaming, connection multiplexing, and KeyPool state management.

The Pipeline: This is where the strict Priority-based middleware chain (Auth -> Cache -> Security -> Rectifier -> Router) lives.

The Rule: These modules must remain in-process.

Layer 2: The WASM Sandbox (The Next-Gen Terraform Pattern - In-Process but Isolated)

What it is: Instead of heavy out-of-process gRPC calls (the traditional Terraform mode), we will embed a WASM runtime (like wazero - zero CGO) inside the Go core.

The Use Case: Complex, community-driven plugins (e.g., advanced Rectifiers for data masking, custom Translators for niche LLMs). Developers can write these in Rust or TypeScript, compile to .wasm, and we load them dynamically. We get multi-language support without the IPC/Network latency of gRPC.

Layer 3: The Brain / Local Enhancements (The Service Mesh / API Pattern)

What it is: External, independent services—specifically local small models (e.g., Ollama, llama.cpp).

The Use Case: Intelligent Router decisions (ML classification) or heavy semantic PII detection.

The Magic: We will use WASM Host Functions to inject Go's HTTP capabilities into the WASM sandbox, allowing a Rust-written WASM plugin to query a local Llama model synchronously for decision-making.

Fork 2: Native rewrite vs. Adapters for the "different-track" features?
Decision: Hybrid (Native Core + WASM Adapters / Delegation).

We will NOT rewrite everything. Our moat is the "depth" of our core features, not just having a million shallow plugins.

Native Rewrite (In-Process): Features that touch the critical latency path or require state locking. Examples: Intelligent KeyPool (quota-aware backoff), transparent 429 retries, and core Translators for OpenAI/Anthropic.

Adapters / Delegation (WASM / External): Features that are heavy on logic but don't hold connection state. Examples: TrueFoundry-style security audits (WASM plugin), CCR routing (delegated to local ML model), Helicone observability (async logging dispatched to an external ClickHouse/gRPC sink).
